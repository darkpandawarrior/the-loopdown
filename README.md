# The Loopdown

Short technical lessons from real projects, each written once and adapted for LinkedIn, dev.to, Hashnode and Medium. The name is *loop* plus *lowdown*. This repo is the whole machine: the writing, the scripts that render and publish it, and the registry below, which is regenerated from the lesson folders.

Projects the lessons come from: Doori, kmp-toolkit, PaymentsLab-KMP, Gaddi, and my time at Dice. There is a [case study on the portfolio](https://siddharth-pandalai.vercel.app/project/the-loopdown).

It does three jobs, which is why the repo looks bigger than a blog:

- **Archive.** My older writing (essays, a few stories, humour), converted to Markdown with frontmatter so none of it is lost. `archive/` holds 10 pieces.
- **Engine.** `scripts/` turns a war story into a LinkedIn post, a long-form article and a rendered card, and exports them. Nothing posts to LinkedIn on its own; the script writes a paste-ready file.
- **Record.** The registry below is generated by `scripts/build-registry.mjs`, and CI fails if it drifts. It currently lists 23 lessons, 17 of them live with a link and 6 still drafts.

## The idea behind the posts

The lessons share a world. An engineer is stuck in a time loop, 52 passes through the same Wednesday, and files field notes on the same bugs each time round. I think seniority is mostly that: you have not learned more code, you have hit the same failure enough times to name it on sight.

A recurring cast carries the bugs. The Concussed Witness is a GPS that lies with total confidence. Doze the Jailer is Android's background execution limits. The Messenger is `CancellationException`, forever mistaken for an assassin. The full cast is in [lore/cast.md](lore/cast.md), the arcs are in [lore/series.md](lore/series.md) and each has a binge page under [series/](series/). The voice rules are in [voice/voice-profile.md](voice/voice-profile.md).

## The Morkinstar Journals

A separate fiction project from the same author, with no shared cast. It grew out of one 2021 story in `archive/` that turned out to hold a whole series. Forty-eight entries in four seasons, about a field correspondent who visits worlds that cannot yet leave them and writes down the story each one tells about its own weather. Every world reports fourteen gods and fourteen monsters, and nobody can name the fourteenth. A sibling set, The Dark Directory, has ten more entries.

Read it on the site: [siddharth-pandalai.vercel.app/anthology](https://siddharth-pandalai.vercel.app/anthology). The index and the story bibles are in [fiction/morkinstar-journals/](fiction/morkinstar-journals/README.md).

```bash
node scripts/morkinstar-plates.mjs   # field plates
node scripts/morkinstar-site.mjs     # builds a local site.html (gitignored, it is large)
```

## How a lesson moves

```
idea -> new-lesson.mjs -> lesson.md   (source of truth, written once)
                              |
              +---------------+----------------+
              v               v                v
        linkedin.md       article.md     assets/card.yaml
                                          -> render.mjs -> card.png
              |               |                |
              +----- I review and edit --------+
                              |
        export.mjs -> dev.to and Hashnode APIs, Medium by hand,
                      LinkedIn as a paste file
                              |
                  meta.yaml records urls and metrics
                              |
                  build-registry.mjs -> the table above
```

Drafts are checked against the voice profile by `scripts/lint-voice.mjs`, which CI runs on every lesson and which flags em dashes and a list of AI tells.

## Running it

Scripts need Node 24 (what CI uses) and a one-time install, which pulls in `@resvg/resvg-js`, `pdf-lib` and Playwright. Cards and carousels render through headless Chromium, so Playwright needs its browser too:

```bash
cd scripts
npm install
npx playwright install chromium
cp ../.env.example ../.env             # then fill in only the tokens you have

node check-setup.mjs                   # read-only readiness dashboard
node new-lesson.mjs "dead reckoning" --pillar location --project Doori --date 2026-07-19
node render.mjs ../lessons/2026-07-19-mileway-dead-reckoning     # card.yaml to card.png
node lint-voice.mjs ../lessons/2026-07-19-mileway-dead-reckoning
node build-registry.mjs                # rewrites the registry and this README's table
node export.mjs ../lessons/<dir>       # dry run: prints the plan, writes paste files
node export.mjs ../lessons/<dir> --draft   # dev.to drafts, reviewable on the site
npm test                               # self-tests for the LinkedIn, post-done and sync-state libraries
```

Accounts, tokens and the posting flow are in [SETUP.md](SETUP.md). `.env` is gitignored. `private/` is gitignored too and holds personal documents and original binaries.

## Publishing

Each lesson goes out as one coordinated drop. dev.to, Hashnode and Medium use their own APIs or an import from the canonical URL; `export.mjs --draft` stages them for review first, and `publish-next.mjs` can publish a lesson whose `meta.yaml` says `status: ready` without me at the keyboard. LinkedIn is never automated: `linkedin-next.mjs` writes a packet to `data/linkedin-queue.md` and raises a notification, I post by hand, then run `npm run post-done <url>` in `scripts/` to record it. One platform holds the canonical URL and the others point at it, so the copies do not compete in search. Every article gets a footer generated from `profile.yaml` listing the series, the cast members involved and the previous lesson.

## Where it stands

The repo started on 2026-08-15. The workflow in `.github/workflows/pipeline.yml` lints the voice, smoke-tests the renders and fails on registry drift. The lessons dated after today in the table are drafts waiting for their slot. The cadence I am aiming for is two to three posts a week from the backlog in `data/backlog.md`; I have not hit it yet.
